# Tour des Viewers — guide pour Claude

Jeu de **défense de tour pour viewers Twitch** (en français). Chaque viewer a un héros autonome (IA réglable) ; le streamer diffuse la bataille dans OBS. Le README décrit toutes les règles du jeu : **le tenir à jour à chaque changement visible**.

## Commandes

```bash
npm start                         # serveur (port 3000 ; PORT et DATA_FILE pour changer)
npm test                          # tests node:test (test/*.test.js) — toujours les lancer avant de pousser
npm run sim:duree                 # durée des parties gagnées (option --normal : parties réelles)
npm run sim:economie              # ressources récoltées / dépensées / restes (options --manche=20 --tour=defense --recolteurs=2)
npm run sim:minijeux              # mini-jeux : un bot joue des expéditions (salle atteinte, morts, rapporté) — options --mode=mine|tous --classe=archer --parade=0.4 --familiers=k_loup,araignee:3 --rentrer=15
npm run sim:classes [spec…]       # équilibrage : manche atteinte par 5 bots d'une même spécialisation
npm run sim:invocations           # nombre de créatures, cadence, ultimes utilisés
npm run sim:passifs               # déclenchements des passifs de classe
npm run sim:bastion               # Bastion : un bot joue des parties (manche atteinte, victoires, durée, rejeu serveur identique) — options --zone=champ|foret|mine|tous --plans=aucun|zone|tous|catapulte,archers/elite --n=20 --detail
npm run captures -- stream        # captures/stream-calme.png et stream-vague.png
npm run captures -- joueur --onglet=hero [--mobile]   # captures/joueur-<onglet>.png (--onglet=bastion pour l'accueil du Bastion)
```

Pages : `/` (joueur), `/stream` (OBS, 1920×1080), `/admin` (compte `admin` / `Malachene`, ou la variable `ADMIN_PASSWORD` ; créé au premier démarrage, l'ancien mot de passe par défaut `123456` est remplacé).

## Architecture

- `shared/constants.js` — **toutes les données et réglages** (partagé serveur + navigateur, `window.GameData`) :
  `WORLD` (carte 1920×1080, `WAVE_ZOOM`, marges d'apparition), `BALANCE` (durées, difficulté, écus, tour), `CLASSES`,
  `SKILL_TREE` / `POST_ULT` / `INITIATION` / `SKILLS` (arbre), `SUMMONS` (invocations), `SKILL_MODS` (bonus spéciaux),
  `SETS` / `TEMPLATES` / `RARITIES` (objets des glaçons), `TOWER_SPECS` + `UPGRADES` (votes : spécialisation de la tour puis ses 8 améliorations), `WALLS` (remparts), `RESOURCES` / `HARVEST` / `upgradeResCost` (pierre, bois, baies : récolte et coûts), `MINI` (mini-jeux : arène, héros, bouclier, sac, seau, salles, butins, améliorations), `PETS` + `petPower` (familiers), `BASTION` (Bastion : prix, carte, tour principale, capacités, `BUILDINGS` (avec la `zone` de leurs plans), `SYNERGIES`, `ROLES`, `BOSSES`, `ZONES` dans l'ordre de déblocage, récompenses) + `bastionCost` / `bastionPlanKeys(zone)` / `bastionPlanZone`, `MOBS`, `BOSS_WAVES`, `NET` (indices réseau).
- `shared/expedition.js` — mini-jeux, partagé serveur + page + bot (`window.Expedition`) : `genRoom` (salle déterministe : graine + numéro), sac / seau (`addRes`, `moveSlot`, `deathSplit`), simulation temps réel `createSim` / `stepSim` (héros, parade, monstres, gardiens, projectiles, familiers, récolte, sortie, renforts).
- `shared/bastion.js` — Bastion, partagé serveur + page + bot (`window.Bastion`) : carte aléatoire (`genMap`, graine), actions de construction (`act` : `['b', type, c, r]`, `['u', id]`, `['s', id, spé]`, `['x', id]`, `['d', c, r]`, `['c']`, `['r']`), statistiques et synergies (`stats`, `synergiesOf`), vagues (`waveSpec`, `launch`, `step`, `useAbility`, `runWave`). **Entièrement déterministe** (hasard dans l'état, pas de trigonométrie) : la page joue, le serveur rejoue chaque vague et doit trouver le même état.
- `server/index.js` — Express + Socket.IO : API joueur/admin, règles de l'arbre (`/api/me/skill`), glaçons, marché.
- `server/db.js` — base JSON (`data/db.json`) ; **toute évolution du format passe par une migration dans `migrateUser`** (drapeau `xxxV1`).
- `server/game/engine.js` — boucle (20 Hz), manches, votes, habitations, statistiques des héros (`refreshHero`), instantanés réseau.
- `server/game/heroes.js` — IA des héros, passifs de classe, invocations (`summonPlan`), ultimes (`wantsUlt` / `useUlt`).
- `server/game/mobs.js` — monstres, apparition (`edgePoint` : bord de la vue dézoomée), dégâts (`damageMob`), récompenses.
- `server/mini.js` — mini-jeux : énergie, expédition (`u.mini.run`, v2), **validation des rapports** de la page (monstres tués, opérations `['h', point, n]` / `['p', butin, n]` / `['pot']`, PV), sac, seau (déposer, renvoyer, rentrer), mort, récompenses, améliorations ; état dans `u.mini`.
- `server/achievements.js` — succès : compteurs `u.ach.c` (`add`, `setMax`), valeurs lues sur le profil (`value`), déblocage + notification (`check`, appelé par `publicUser` et en fin de partie), titre équipé `u.title` (`setTitle`, `titleOf`) ; liste dans `ACHIEVEMENTS` / `ACH_CATS` (constants). Le titre va au stream via le roster (`tt`).
- `server/anticheat.js` — anti-triche : alertes par compte `u.cheat` (`flag`, score qui baisse de 2/jour, mini-jeux suspendus à 30), débit (`allow`, seaux à jetons), comptes liés par IP **hachée** (`seen`, `linked`, `transfer`), limites des expéditions (`miniLimits`, `reinfEarliest`) appliquées dans `mini.js` `applyReport` ; panneau admin `/api/admin/anticheat`.
- `server/bastion.js` — Bastion : partie (`u.bastion.run` : état G, actions appliquées `nops`, capacités `abil`), 50 Grêlons (remboursés à la manche 30), actions renvoyées sans doublon (`applyOps`, `from`), **vague rejouée par le serveur** (`endWave`, pas plus vite que ×3), récompenses (XP en fin de partie, plans de la zone tirés sans doublon `dropPlans` et œuf aux gardiens, zones débloquées), classement (`ladder`).
- `server/pets.js` — familiers des mini-jeux (chenil, œufs, repos/régénération, XP, familier principal du stream) ; état dans `u.pets`.
- `server/twitch.js` — chat Twitch anonyme (!join, !lier, votes) et abonnements (Grêlons).
- `public/js/art.js` — **tout le dessin** : héros pixel art composés (`buildHeroPixels`, armes `drawWeaponPx`, monture), monstres en sprites, bâtiments, tour, projectiles.
- `public/js/sprites.js` — **généré** par `tools/pixelart/export.py` (ne pas éditer à la main) ; sources Python dans `tools/pixelart/` (`s_*.py`, `build.py` pour un aperçu).
- `public/js/stream.js` — rendu du stream (caméra, dézoom + brume pendant les vagues, effets, HUD, votes).
- `public/js/mini.js` — onglet Mini-jeux : camp (améliorations, familiers, œufs) et jeu vu du dessus (boucle `stepSim`, commandes clavier / souris / tactiles, HUD, panneaux du seau, des récompenses, de pause et de fin, sons) ; rapports envoyés au serveur (`call`, ops rejouées sur l'inventaire renvoyé). `public/js/minidecor.js` — décors vus du dessus (3 × 3 × 6), sorties, fontaine.
- `public/js/bastion.js` — onglet Bastion (accueil, collection de plans, carte avec caméra zoom / déplacement, plein écran paysage sur téléphone, panneaux, vagues animées, envois dans l'ordre via `enqueue`) ; `public/js/bastionart.js` — sprites pixel art du Bastion (bâtiments, tour principale, obstacles, sol), dessinés sur une grille de pixels avec contour automatique.
- `public/js/audio.js` — son de tout le site (`window.GameAudio`) : réglages communs (bouton 🔊 du haut de page), ambiance « chill » sur tous les onglets, séquenceur de musique unique (`playMusic(clé, thème)` / `stopMusic(préfixe)`) utilisé par les mini-jeux et le Bastion, bruitages d'interface.
- `public/js/player.js` — page joueur (arbre de compétences en étoile, équipement, glaçons, IA, compte).

## Règles de conception (demandées par le propriétaire)

- Tout le texte visible est **en français**, commentaires de code aussi.
- Style graphique : **pixel art clair et coloré** (pas de thème sombre pour le jeu), contours foncés `#120c0a`.
- Partie **classique gagnée ≤ 60 min** (cible ≈ 45-52 min), partie rapide ≈ 12-15 min. Vérifier avec `npm run sim:duree` après tout changement de durée, de vitesse ou d'apparition des monstres.
- **Pas de gros surplus de ressources** en fin de partie (vérifier avec `npm run sim:economie`) ; les écus n'existent plus.
- Arbre : centre Paysan (identifiant interne `habitant`), branche de classe (niveau 7), sous-branche (initiation 3/3), 5 compétences, ultime (niveau 30), 2 compétences d'après-ultime ; **2 points requis dans le nœud précédent** ; aucune compétence d'avant l'ultime ne charge l'ultime.
- Invocations : 1 créature par nœud, 2 au rang 3 ; **6 au plus, 9 avec la compétence d'après-ultime** ; une toutes les 10 s, 5 s après une mort ; statistiques relatives aux statistiques réelles du héros.
- Votes : 1er vote = spécialisation de la tour (attaque, défense, soin, mage) ; ensuite 3 choix : 2 améliorations de la tour + Pacte de sang (remplacé par la Résurrection s'il y a un mort, sinon parfois par la Vitalité de la nature). Plus de « Économiser » ; sans vote, choix au hasard. Coûts en ressources : principale de la tour + 1/3 d'une autre (mage : deux équilibrées).
- Mini-jeux **en temps réel vus du dessus** : 1 énergie / 6 h (3 max) ; ZQSD (Maj = sprint ×1,5 avec jauge d'endurance ; Espace = roulade : bond puis 1 s d'invulnérabilité, 50 d'endurance, pas de récupération pendant ce temps), clic gauche = attaque **et** récolte vers la souris, clic droit = bouclier (parade parfaite = dégâts renvoyés), E compétence, A potion, F seau (Espace n'ouvre plus le seau). Salles générées par graine (identiques page / serveur) ; sortie après 10 s (cavité dans la caverne, ouverture sur un côté ailleurs), renforts 20 s après l'entrée dans la salle puis toutes les 5 s, aucun en salle d'élite / de gardien (déterministes, numérotés à partir de `REINF0`, **jamais de butin**) ; 3 monstres au départ, +1 toutes les 6 salles, 8 au plus (`startMobs`), renforts retardés de 2 s par monstre en plus (`reinfAfter`, 30 s au plus), qui foncent sur le héros, « Rentrer » refusé tant qu'ils vivent ; torche à côté du seau ; forêt (sombre, arbres serrés) et clairière (claire, clôtures) bien distinctes ; fontaine 10 PV/s pendant 3 s ; points de récolte rares (le niveau max de Flair / Gros butin redonne l'ancien nombre et la taille) — ne pas changer les coûts des améliorations sans demande ; élite toutes les 5 salles, gardien toutes les 10 (récompense au choix, œuf 15 %) ; type de salle affiché avec son numéro. Sac 5 cases (+5/niv., poche sécurisée au max), 1 case = 15 ressources ou 1 butin ; seau (caverne) / charrette (forêt, clairière) 10 cases (+10/niv.), posé à un endroit fixe tiré au hasard dans chaque salle (`room.cart`, obstacle), « Renvoyer » = à l'abri et retour 2 salles plus tard, « Rentrer » = fin ; jeu ralenti pendant le dépôt. Mort : tout le non-renvoyé est perdu sauf 25 % des ressources du sac. La page simule, **le serveur valide** et garde l'inventaire ; statistiques propres aux mini-jeux (`MINI.BASE` + `miniStats`), dont vitesse (150 de base), endurance et vitesse d'attaque payées en butins des monstres ; les monstres frappent d'un peu plus loin. Vérifier avec `sim:minijeux` (bot) après un changement d'équilibrage. Familiers : chenil 10 glaçons, œuf (30 min d'incubation, monstre de la zone, rareté ; chaque monstre n'existe que dans une zone — test dans `pets.test.js`), 2 actifs qui suivent le héros, 20 % des coups sur eux (les familiers « à distance » ne sont touchés que par les monstres qui tirent), PV régénérés avec le temps (K.-O. → repos jusqu'à 50 %), potion de familier (butin `fiole` : élite 10 %, gardien 25 % ; `pets.heal` au camp, soin complet), évolution esthétique, familier principal niv. 10+ sur le stream. Remparts/murets = vrais murs à PV (`refreshWalls`, `wallBlocking`). Soin d'entracte 10 % → 75 % ; pas de retraite ni de soin continu près de la tour. L'admin peut donner une amélioration pour tester (action `upgrade`).
- **Bastion** (onglet 🏰, tower defense solo) : carte **24 × 14** générée au hasard à chaque partie, **tour principale au milieu** (grande zone d'attaque ≈ territoire de départ), **chemin toujours aléatoire** depuis un bord ; zones **Clairière → Forêt → Caverne**, chacune plus difficile que la précédente ; 50 Grêlons, remboursés en atteignant la manche 30 ; victoire à la manche 30 (zone suivante), puis mode infini au choix ; construction sans limite de temps ; bâtiments d'attaque (avec une **zone d'attaque** affichée), support, production, richesse : 3 niveaux puis une spécialisation sur 2 ; **défrichage payé en or** ; **synergies entre bâtiments qui partagent un côté** (affichées sur la carte) ; tour principale améliorable (PV, territoire, niveau des bâtiments, capacités) ; **uniquement des bâtiments** (pas de héros) ; **plans propres à chaque zone** (champ `zone` des bâtiments), lâchés au hasard par les gardiens, **jamais en double** ; récompenses : XP, plans et œufs (15 % aux gardiens) — **aucune ressource des mini-jeux** ; **sans plan, un joueur ne doit pas aller loin** (bot : ≈ manche 20, aucune victoire). Sur téléphone : plein écran paysage (tourné si le téléphone reste en portrait), zoom et déplacement. Après un changement d'équilibrage : `sim:bastion` (avec `--plans=aucun` et `--plans=zone`) ; le rejeu serveur doit rester identique (0 vague différente).
- Succès (onglet 🏅) : chaque succès débloque un titre équipable (stream, classement, en-tête) ; tout nouveau type de jeu ou d'objet mérite ses succès (ajouter une série avec `achSeries` et un compteur `ach.add`) ; titres uniques (test dans `achievements.test.js`).
- Anti-triche : tout ce que la page envoie (rapports des mini-jeux, compteurs) doit être **borné côté serveur** ; après un changement d'équilibrage des mini-jeux, `sim:minijeux` ne doit afficher **aucune alerte anti-triche** (un joueur honnête ne doit jamais être signalé). Ne jamais enregistrer d'adresse IP en clair.
- Chaque classe sauf le Paysan a un passif (champ dans `CLASSES`, texte généré par `passiveLines`, effet dans `heroes.js` / `mobs.js`).
- Les statistiques d'un héros sont **figées pendant une bataille** (profil verrouillé), les récompenses versées en fin de partie.

## Façon de travailler

1. Modifier → `npm test`.
2. Mécanique de jeu : la simulation adaptée (`tools/sim/`). Visuel : `npm run captures …` puis regarder l'image.
3. Mettre à jour le README (et la page Règles dans `player.js` si besoin).
4. Rappeler au propriétaire de **redémarrer le serveur** (et Ctrl+F5 sur le navigateur / « Actualiser le cache » dans OBS) : beaucoup de « bugs » signalés venaient d'un serveur ancien.

Pièges connus : `startedBranch` / `requiredRank` doivent rester identiques côté serveur (`server/index.js`) et page (`player.js`) ; un nouvel identifiant de projectile, zone ou drapeau réseau s'ajoute dans `NET` (constants) et se dessine dans `stream.js` / `art.js`.
